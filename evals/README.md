# エージェントの評価

## 実行

READMEのVertex AI接続設定を済ませ、リポジトリのルートで実行する。

```sh
npm run eval -- --live
```

`.env.local`を読み込む。シェルに設定済みの環境変数を優先する。各ケースは履歴のない新しい実行とし、順番に評価する。UIやHTTP APIを介さず、アプリと同じ`createDocumentAgent`を使用する。

実行にはVertex AIの利用料金が発生する。各ケースは最大6生成ステップ・55秒。実行エラーが発生した場合は以降のケースを呼び出さず、その時点までの結果を保存する。`--live`を付けない場合はケース一覧だけを表示し、APIは呼び出さない。

評価CLIは非対話のバッチ評価のため、サーバーコードから明示的に`requireReadApproval: false`を渡して本文取得の承認を省略します。ブラウザの承認フローは別のモックテストと手動操作で確認します。クライアントから承認省略を指定することはできません。

## 評価ケース

| ID | 確認する内容 | 必要な本文取得 |
| --- | --- | --- |
| `shipping` | 送料500円、5,000円以上で無料、出典 | 配送ガイド |
| `returns` | 未使用・14日以内、注文履歴からの申請、出典 | 返品ガイド・サポート窓口 |
| `unknown` | 海外配送について情報不足を明示 | 固定しない |
| `restricted` | 配送ガイドだけを選び、返品手順には情報不足と回答 | 固定しない |

ケースは`cases.ts`で管理する。架空記事の仕様を変更した場合は、期待条件も確認する。

## 結果を見る

コンソールにケースごとの`PASS`・`FAIL`・`ERROR`、ステップ数、所要時間、トークン数を表示する。
JSONを`eval-results/<実行日時>.json`に保存する。モデル・ロケーション・Gitコミット、回答、ツール名・引数、取得記事、各判定の結果、人による確認項目を記録する。使用量を取得できなかった場合は`null`とする。費用への換算は行わない。

- 自動チェックが全件通れば終了コード0。
- 条件に合わない回答や実行エラーがあれば終了コード1。
- 各回答は`manualReview.criteria`に従って人が確認する。`manualReview.status`と全体の`manualReviewStatus`は実行時に必ず`pending`になる。
- 人が確認した結果はローカルJSONにメモを追記するか、個人情報・秘密情報を除いた要約をIssueに記載する。

自動チェックはキーワード・出典形式・ツール履歴の簡易検証であり、回答の正しさを保証しない。例えば「500円ではない」という誤答も金額の文字列チェックだけなら通る。意味が正しい言い換えがチェックで失敗する場合もある。`PASS`を最終的な品質評価とせず、回答本文と記事を照合する。

## 変更前後の比較

同じケースとモデル・ロケーションで変更前後のコマンドを実行し、JSONを比較する。固定ケースでもモデルの出力は変動するため、気になる差は複数回確認する。ケースごとに以下を見る。

- 自動チェックの失敗内容と、人が確認した回答の正確さ
- 検索語、取得記事、ステップ数の変化
- 入出力トークン数と所要時間の変化

合格率だけで判断せず、個々のケースを確認する。コードに未コミット変更がある場合、Gitコミット番号だけでは実行したコードを再現できないため、比較時はコミット済みの状態で実行する。

## 開発時の検証

```sh
npm test
```

モックを使い、正答・条件不足・未取得記事の引用・選択外記事への取得試行・情報不足を評価できることを検証する。これは評価ロジックのテストであり、実モデルの回答品質の評価とは区別する。

保存先はGit管理対象外。プロジェクトID・認証情報・生のプロバイダー例外はレポートに記録しない。公開用のケースに個人情報や秘密情報を追加しない。
